Cell towers collapse. GPS handhelds run out of charge within hours. Rescue teams enter rubble-filled zones with no communication layer and no way to locate survivors. The survivors who could signal — can't. The gap isn't the rescue technology. It's power and connectivity when infrastructure is gone.

The Product
One wristband. Two core innovations.

HARVEST SOS harvests energy from four body-ambient sources simultaneously and uses it to power an infrastructure-independent emergency beacon — no cell towers, no satellite subscription, no external charging needed.

①
Adaptive Energy Management
A microcontroller (STM32L0) polls four harvesting sources — kinetic, thermoelectric, photovoltaic, and piezoelectric — every 500 ms and dynamically routes power from whichever active combination is producing most. Individual MPPT per source prevents losses from passive combining.
EST. OUTPUT: 3–52 mW (scenario-dependent)
②
Mesh-Relay Emergency Beacon
Instead of Bluetooth (10 m range), HARVEST transmits GPS coordinates or a device-ID distress signal on 865 MHz LoRa. Each unit also auto-relays packets from other HARVEST units in range — building an ad-hoc rescue mesh with no towers. GPS-lock lost (e.g. underground)? Falls back to ID-only broadcast automatically.
EST. RANGE: 2–15 km/hop · POWER: ~0.8 mW avg
The Engineering Investigation
Can adaptive harvesting outperform
single-source and passive combination?
Mode A — Baseline
Single Best Source
Only the highest-yielding source connected. All others off. Represents what conventional single-technology wearables achieve.
Expected: ~3–30 mW (est.)
Mode B — Naive Multi
Passive Sum
All 4 sources on a shared rail, no MPPT, no gating. The naive approach — should outperform A, but loses energy to MPP mismatch and backflow.
Expected: ~5–35 mW (est.) — wastes 20–40%
Mode C — HARVEST
Adaptive System
ADP5092 PMIC per source, STM32L0 polling, dynamic gating, and load routing active. Individual MPPT + backflow prevention + condition-aware switching.
Target: ≥25% gain over Mode B — prototype decides
Hypothesis: Mode C outperforms both A and B in every condition, with the largest gap in mixed or changing environments. We don't pre-fix the percentage — the prototype data determines whether the gain is 10%, 25%, or more.
Why Optimisation Works — The Three-Layer Stack
Each layer captures losses the previous one misses.
1
Per-Source MPPT
ADP5092 × 4
Each harvester has its own Power Management IC performing Maximum Power Point Tracking — continuously sweeping voltage to find the peak of the P-V curve. The source operates at its theoretical maximum regardless of load variation, instead of being dragged off-peak by a shared bus.
+20–35%
2
Backflow Gating
STM32L0 + N-FET gates
STM32L0 polls each source's output every 500 ms. Any source below its forward-voltage threshold is switched off at its N-FET gate. This prevents weak sources from becoming reverse loads — a real, measurable loss mechanism in passive multi-source circuits that is invisible until you measure it.
+5–15%
3
Dynamic Load Routing
STM32L0 firmware
When conditions shift — cloud covers sun, wearer stops walking — the controller re-ranks sources by live output and re-routes the SOS module's power draw to the strongest active combination. No source carries load beyond its capacity; no surplus source sits idle while the system starves.
+5–10%
Σ
Combined Adaptive System
All three layers active
MPPT extracts each source's peak → gating prevents all backflow losses → dynamic routing keeps the strongest source under load at all times
+25–40% est.
Why passive combining alone fails: On a shared rail, bus voltage is set by the strongest source. Every weaker source sees a forward voltage above its output — it stops contributing or reverses. Passive sum sounds additive. In practice it discards up to 40–60% of theoretical yield.

Prototype & Validation
Three phases. One central experiment.
Phase 1 — Characterisation
Source Mapping
  • Breadboard each source individually to a load resistor
  • Measure raw output in 5 conditions: resting, walking, outdoor sun, indoor, night
  • Build empirical P-V curves for each source
  • Identify which source dominates in which condition
OUTPUT: Per-source power models and MPP profiles
Phase 2 — Core Experiment ★
Mode A vs B vs C
  • Add STM32L0 + ADP5092 PMICs to the rig
  • Run Mode A, B, and C back-to-back in identical conditions over 4 hours each
  • Log total harvested energy per mode
  • Let the data determine the gain — 10%, 25%, or otherwise
OUTPUT: Measured % improvement of adaptive over passive
Phase 3 — Full System
Live Demonstration
  • Full wristband with LoRa SX1276, GPS, and strobe assembled
  • Two-unit mesh relay test: Wearable A → B relay → receiver → dashboard
  • GPS lock time, GPS-loss fallback behaviour, and strobe visibility at 200 m
TARGET: Signal relay >2 km · GPS lock <5 s · Strobe visible at 200 m night
